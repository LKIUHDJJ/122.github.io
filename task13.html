Task13 第十三个帖子 矛盾

# Bugku CTF｜矛盾 WEB WriteUp 题目信息 - 题目：矛盾 - 类型：WEB 一、题目分析 打开靶场页面，结合评论可以推断 PHP 核心逻辑，这道题考察 **PHP 弱类型松散比较`==`**。 推测源码逻辑： **矛盾条件：** 1. `$num != 1`：变量**不等于数字 1** 2. `$num == 1`：变量**松散比较等于数字 1** 两个条件看上去互相冲突，所以题目名字叫 “矛盾”，利用 PHP 弱类型转换实现同时满足。 PHP 字符串与数字弱转换规则 当字符串和数字使用`==`做比较时，PHP 会**把字符串从开头解析数字，遇到非数字字符直接截断，后面全部丢弃**。 示例： - `"1a"` 和数字 1 比较：PHP 提取开头数字`1`，`"1a" == 1` → **true** - 但是字符串`"1a"`本身不是数字 1，所以 `"1a" !=1` → **true** ✅ 这样两个矛盾的条件全部成立，拿到 flag。 ## 二、Payload 构造 ### Payload1：字母后缀截断（最常用） /?num=1a - `num=1a`：字符串`"1a"` - `$num ==1`：取开头数字 1 → true - `$num !=1`：字符串 "1a" 和整型 1 不完全相等 → true Payload2：%00 空字符截断 /?num=1%00 `%00`是 url 编码的 null 字符，`"1\0"`在 PHP 弱比较同样被解析成数字 1，同样满足双重条件。 > > 其他可用 payload：`/?num=1abc`、`/?num=1xxxxxxxx`，只要**以数字 1 开头，后面带上任意非数字字符**都可以。 三、原理详解 1. **`==`松散比较 vs `===`强比较** - `==`：先做**类型转换**，再对比值； - `===`：同时对比**值 + 数据类型**，不会做自动类型转换。 如果题目是`===`，本方法完全失效。 2. `"1a" == 1`执行过程 1. 一边是字符串`"1a"`，一边是 int`1`； 2. PHP 将字符串转为数字，从起始位置读取数字：读到`1`，接下来字符`a`不是数字，停止解析； 3. 字符串转数字结果得到`1`，`1 ==1`条件成立； 4. 但原始变量仍然是字符串`"1a"`，所以`"1a" != 1`条件也成立。 两个看起来互斥的判断同时为真，也就是题目的 “矛盾”。 四、踩坑记录 - ❌ `?num=1`：`$num !=1`条件不成立，拿不到 flag； - ❌ `?num=a1`：开头不是数字，转数字得到 0，`0==1`为 false； - ✅ 必须：**开头是数字 1，后面跟任意非数字字符**。 五、考点总结 1. PHP 弱类型松散比较`==`字符串转数字自动截断漏洞； 2. CTF 经典矛盾条件：`$x!=1 && $x==1`； 3. url 传 GET 参数的基础用法。 > > 扩展同类题型：备份是个好习惯（md5 弱比较），都是 PHP `==`弱比较系列。
