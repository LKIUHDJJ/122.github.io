Task29 第二十九个帖子 GET

Bugku CTF《GET》WEB题目基础信息

题目名称：GET

题目类型：WEB

题目提示：无

题目描述：flag{}，点击启动场景访问网页，页面显示文字：请输入 flag。

考点分析：

本题考察 PHP 的GET 传参，GET 参数是直接附加在浏览器 URL 地址后面的参数。

页面的后端 PHP 逻辑大致如下：

<?php
$what = $_GET['what'];
if($what == 'flag'){
    echo "这里输出真正的flag";
}else{
    echo "请输入flag";
}
?>

直接打开原始页面，URL 不带任何参数，$_GET['what']不存在，条件不成立，页面只会打印 “请输入 flag”。

我们需要手动在浏览器地址栏添加 GET 参数 what=flag，满足后端判断条件，页面就返回 flag。

很多新手会在网页页面找输入框，页面没有表单输入框，不能在页面上打字提交，参数必须写在浏览器网址 URL 当中。

方法 A：浏览器地址栏直接拼接参数（最简单，推荐，不需要工具）

点击启动场景，复制浏览器地址栏的原始网页链接。

例如原始地址：http://xxx.bugku.com/xxx/index.php

在 URL 末尾拼接 ?what=flag

完整的 URL 示例：http://xxx.bugku.com/xxx/index.php?what=flag

语法小知识：?是 URL 参数开始标记，what是参数名，flag是参数的值。

将拼接完成的完整链接粘贴到浏览器地址栏，按下回车访问页面。

页面不再显示 “请输入 flag”，直接输出完整flag{...}，复制提交平台即可。

方法 B：Burp Suite 抓包修改请求（备选方案）

打开靶场原始页面，使用 Burp 代理抓包，捕获浏览器发出的 GET 请求。

在请求行的 URL 末尾手动添加 ?what=flag。

将修改后的请求放行发送给服务器。

在 Burp 返回的响应包里面读取页面返回的 flag 字符串。

高频踩坑点梳理：

在网页页面寻找输入框：页面没有文本输入框，不能在页面上打字输入 flag，参数写在 URL 地址栏，不是网页内容。

符号写错：把?写成&，&用于多个参数之间分隔，第一个参数必须使用问号?开头。

错误示例：xxx.php&what=flag （❌错误，拿不到 flag）

正确示例：xxx.php?what=flag（✅正确）

参数名拼写错误：写成What=flag、wHat=flag，PHP 的 GET 参数区分大小写，参数名必须小写what。

直接在页面刷新反复等待：页面本身没有交互，刷新原始地址永远只会输出 “请输入 flag”，必须带上 URL 参数。

原理复盘总结：

GET 请求参数附加在 URL 上，$_GET['参数名']用来读取网址携带的数据。本题没有前端表单，所有输入全部由 URL 传递。

做题记忆：WEB 题目看到$_GET[]，优先想到在地址栏?参数名=值。
