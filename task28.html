Task 第二十八个帖子 计算器

Bugku CTF《计算器》WEB 题目基础信息 题目名称：计算器 题目类型：WEB 题目描述：计算正确即可得到 flag，点击启动场景访问网页。 考点分析 打开网页是一个简易网页计算器页面，页面会随机生成一道算术计算题，需要你把计算结果填入输入框提交。 前端输入框设置了maxlength属性，限制输入字符最大长度。 当题目运算结果数字位数超过输入框允许的最大字符长度时，网页输入框会阻止你输入完整答案，直接在页面上无法填完数字。 关键点：maxlength属于前端 HTML 限制，仅仅只是浏览器层面的限制，修改浏览器本地页面元素就可以绕过这个限制，后端没有做对应的强硬校验。不是 SQL 注入、不是代码执行，就是修改前端 DOM 属性绕过输入长度限制。 步骤一：访问靶场网页 点击启动场景，打开计算器网页。页面展示随机算术式子，下方有输入答案的文本框、提交按钮。 简单的加减法可以正常输入，遇到结果位数比较大的算式，输入框输到一半就无法继续敲数字，这就是题目的坑点。 很多同学反复刷新页面，企图刷出一个数字很小的算式，浪费大量时间，刷新并不能稳定得到短数字题目，正确解法是修改前端限制。 方法 A：浏览器开发者工具修改 maxlength（Chrome/Edge，推荐） 将鼠标光标放到答案输入框上面，鼠标右键，选择【检查】（或者快捷键 F12，打开开发者工具）。 在 Elements（元素）面板，自动定位到输入框对应的标签代码。 可以看到标签带有属性类似 maxlength="5"，这个数字就是最多允许输入多少个字符。 双击maxlength后面引号里面的数字，把数值修改成一个很大的数字，例如改成100，按回车确认修改。 也可以直接把整段maxlength="x"属性直接删掉，输入框就不再限制字符长度。 关闭开发者工具，回到网页页面，此时输入框不再限制输入字符数量。 手动算出页面上算术表达式的正确结果，完整把数字填写进输入框，点击提交按钮。 页面返回 flag 字符串，复制按照格式提交平台。 高频踩坑点梳理 反复刷新页面赌小数字：不断刷新希望拿到位数少的算式，效率很低，不是题目设计的预期解法。 修改错标签：开发者工具里面 HTML 标签很多，确认修改的是答案输入框 input，不要修改按钮或者其他标签。 只修改页面显示，提交数据包没改：用开发者工具改完属性一定要在网页页面输入正确答案；如果使用 Burp，要在数据包内写正确结果。 计算算术题算错数字：题目只是普通加减运算，数字很大，手动计算仔细，答案数字错了也拿不到 flag。 误以为存在注入漏洞：本题没有命令执行、没有 SQL 注入，仅仅前端长度限制绕过。 原理复盘总结 这道 WEB 题考察前端和后端分离的安全思想：maxlength是浏览器前端的限制，只能阻止普通用户在页面输入，不能约束向后端发送的数据包。 前端的一切 HTML、JS 限制全部都可以被客户端修改绕过，重要业务校验逻辑必须放在服务端，不能只依靠浏览器做校验。出题人故意只在前端设置输入长度限制，后端只校验提交的数值是否数学正确。 ✅ flag： flag{Calculator_1s_easy}
